# CDate: Chabad Calendar (notes for Claude)

This repository is a hosted web app: a Chabad/Jewish calendar that is installed on the owner's phone (Pixel 6 Pro, Android) from GitHub Pages and sends push reminders. The owner works **from a phone only** and is not a programmer. Explain things in plain words, one step at a time, and do the git work yourself.

- Live site: https://mosheliberman03-maker.github.io/CDate/ (GitHub Pages, `main` branch, root folder)
- Push server: https://cdate-push.mosheliberman03.workers.dev (Cloudflare Worker named `cdate-push`, source in `server/worker.js`)
- Owner's location default: Foshan, China (timezone Asia/Shanghai). Users: fewer than a few dozen people.

## Files
| File | What it is |
|---|---|
| `index.html` | The whole app in one file (HTML + CSS + JS, about 380 KB). Edit it directly. |
| `sw.js` | Service worker (registered for every user on load): shows push notifications, focuses the app on tap, and keeps one saved copy of the app (cache `cdate-app-v1`): opening answers instantly from it and fetches the newest copy in the background; if that changed, it messages the page (`cdate-update`) and a "Tap to update" button appears. Fonts, `assets/` and icons are served from cache `cdate-static-v1` (stale-while-revalidate: instant and offline, refreshed in the background; rename a file to force a change through at once). |
| `hayomyom-en.json` | English Hayom Yom (Chabad.org translation, used with permission; the owner holds the written permission), keyed `"<monthKey>-<day>"` like `Ki-19`, `AI-14`. Each entry `{h: original date heading, p: [paragraph HTML with only b/i/br], t: 1 if translated in the app}`. 12 entries (13 dates) were translated from the Hebrew/Yiddish because the collector picked up the original. Loaded by `hyFill()`; the service worker keeps a saved copy. |
| `tools/` | The phone-browser bookmark tools used to collect it (Chabad.org blocks server downloads, 403); `prefetch-shiurim.js` (nightly shiur texts); `worker.html` (copy page for the server code). |
| `sefaria/` | Shiur texts saved nightly by `.github/workflows/shiurim.yml` (about 03:15 China time; yesterday to 8 days ahead). Sefaria's Cloudflare protection blocks live requests from the app on the owner's phone and from Cloudflare Workers, but answers GitHub's servers. The script runs the app's own reader (`rdBuild`) headless and saves the trimmed Sefaria replies under the names `rdLocal()` looks for. Texts are kept (they repeat in later years); day schedules older than 3 days are deleted. |
| `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png` | Install metadata and icons (a plain aleph in a serif font). |
| `server/worker.js` | Cloudflare Worker source. **Not served from here**: changes must be pasted into the Cloudflare dashboard by the owner (Workers & Pages, then cdate-push, then Edit code, then Deploy). Needs KV binding `KV` and cron `* * * * *`. |

**GitHub Pages publishing can get stuck** ("Deployment request failed … due to in progress deployment"), especially after several quick pushes. Fix: run the `unstick-pages.yml` workflow (cancels deployments GitHub still thinks are in progress, then requests a fresh build). Avoid many pushes to `main` in a row. `tools/worker.html` has a Copy button for pasting `server/worker.js` into Cloudflare from the phone.

Do not add files named `index (1).html` or similar: only `index.html` is served. GitHub Pages tells browsers to cache for about 10 minutes, but the service worker bypasses that: after Pages publishes (1–2 minutes), the next open shows "Tap to update" (or the open after that shows the new version). If the app was left open in the background, a "Tap to update" button appears when it returns after 2+ minutes.

## Inside index.html (main pieces, by function name)
- **Calendar core:** `hd()` Hebrew date, `t0` today (rolls over at sunset), `sel` selected day, `LC` location `{n,la,lo,tz}`, `setLoc(n,la,lo,tz)`, `zAt()` zmanim, `render()`, `panel()`, `upd()`. Study tracking lives in `DN` (key `YYYY-MM-DD` → `{chumash,tehillim,tanya,rambam3|rambam1,hy}`); `tog(k)` toggles one.
- **Repeating plans only on today:** the user's own daily / every-other-day / weekly plans (`routine(e)`) are shown only on today. Display code uses `infoD(dt)` (filtered); `info(dt)` keeps everything for reminders and for cancelling. Use `infoD` for anything new that displays days.
- **Test account** (log in with username `test`, password `test`; created on first login): a `Date` patch at the top of `<head>` adds `window.__TOFF` (key `cc_test_toff`; the real one is `window.__RealDate`), so the whole app runs on a movable clock. On first login the test script at the end of `index.html` picks a "demo day" in the next ~14 months with the most kinds of special days (`cc_test_demo`), adds labelled examples of any missing kinds to `idx` for that day (test account only), seeds plans through the assistant (`aiInterpretSeg` + `aiCommit`), a yearly event, a 6-day streak, 2/4 shiurim and a saved Tanya place, and opens on that day at 3 PM. A ×3 pill at the top (`#ccTestBadge`) always shows the simulated date/time (tap it = Real now), so the movable clock is never mistaken for the phone’s time. "Test tools" in the ⋯ sheet (`#testTools`): date + time slider, Sunrise / Midday / Sunset / Night (same day) / Demo day / Real now, Play sun/moon opening, Play logo intro (reload), Reset test account (clears `cc_profile_test_*`). Nothing changes for other accounts (`window.CC_TEST` is unset). **Standing rule (owner): every new feature, where it makes sense, gets an on/off switch in Test tools** (`FLAGS` in the test script → class `tt-off-<id>` on `<html>`, stored in `cc_test_flags`; write the feature's CSS/JS so that class turns it off). Current switches: `glassui` (matching glass cards/sheets/buttons), `aim` (semicircle faces the sun/moon), `capdate` (caption under the big date), `swave` (softer night waves), `side` (big date when the middle is empty), `dome` (semicircle swivel).
- **Updates: "What's new" popup + live tours (STANDING RULE).** Every feature update must bump `CC_VER` and add a `CC_LOG` entry. Small change -> `{v, new:[…]}` (shown in the glass What's-new popup `ccNewsPopup` right after the user taps "Tap to update"; `ccWhatsNew(sv)` compares per-profile `cc_seen_ver_<u>` to `CC_VER` on load). Whole new feature -> also `{feature, tour:'<id>'}` and add an `<id>` step-set to `SETS` inside `ccTourStart`, so the popup's "Show me" runs a live tour. New users get the onboarding tour instead (and are marked current, no backlog); first-time-tracked returning users see only the latest entry.
- **Guided tour** `ccTourStart(key,replay,which)` (revamped): a moving SVG spotlight + a glass card (Next/Skip/progress) over the real UI, with live demos (types a chavrusa into the assistant, etc.). `which` picks a set in `SETS` (`onboard` default, `app`, …). Replay from ⋯ → Help. Onboarding copy matches the current UI (swipe/week strip to change days — no ‹› arrows, assistant-first, shiur reader, reminders+app). Card uses the glass tokens (`--gx-*`).
- **Per-profile storage:** `AK(key)`, `ST(key,default)`. Local profiles and a login gate exist (`cc_local_profiles_v1`).
- **Opening logo animation:** the `#intro` overlay script (10.7 s of timeline played at `SPEED` 1.65, about 6.5 s; late frames pause it instead of skipping). Note: a `<style id="android-blank-screen-fix">` tag sits *inside* the main CSS as text, so its `#intro{display:none}` rule is dead. Leave it: "fixing" it would remove the intro the owner likes.
- **Live sky:** `SKY`, `skyCompute()`, `skyPalette()`, `skyApply()`, `skyTick()` (every 30 s). Sun and moon artwork is procedural: `artSunCanvasKey()` (fields precomputed once in `artSunFieldRows()`), `artMoonCanvas()`, plus `artSunUrl()` / `artMoonUrl()` for `<img>` use.
- **Night redesign (main screen, from the owner's night mockup):** styles live in `<style id="cc-night-ui">` (glass vars `--gl-bg/--gl-bd/--gl-tx`, `--navy`, `:root[data-night="1"]` overrides). `skyNightAmt(p)` fades `#skyNight` (navy gradient) and sets `data-night`.
  - **Silk background:** WebGL shader (`#skyGL` canvas in `#skyWaves`, fallback `skyRibbonsSvg()`): twisting translucent silk strips lit by one light (`GLS`), tuned to look liquid/glassy rather than metallic (owner): soft broad highlights, Fresnel-brighter curved parts, faint iridescence between `--rbf` violet-blue and `--rbe` icy cyan, almost no brushed fibres. At night a softness uniform `uK`=1 dulls them further (softer edges, much weaker highlights, ~30% fainter) so they stay in the background (owner); Test tools switch `swave` sets it back to 0. It stays fixed behind the page; scrolling makes the ribbons undulate (scroll drives shader time `uT`, no vertical parallax). Drawn only when scrolling or size/colours change (no idle animation), at `Q=.4` resolution, max ~60 fps, paused during the logo intro.
  - **Glint:** only animated glints, no static highlights anywhere (owner's rule). `glassShine()` sets `--gg` (bright arc on the rim, `::after` conic) and `--hx/--hy` (soft glow, `::before`) on the glass chips (`GL_SEL`: week panel, pill, dock, hint, + button); soft and cool-tinted, like light on water rather than a polished metal edge; it moves only while swiping (0.3°/px, own direction per chip via `glSeed`).
  - **Independent pieces:** floating and scroll depth are pure CSS (`flY`/`flX` on `translate`, plus `flP` on a scroll timeline, `animation-composition:add`; per-piece `--fa/--fy/--fx/--fd/--pd`) for the moon + trail, the dome (`.sky-scene::after`), pill, date lines, week panel, + button and dock. No per-frame JS (the owner found that glitchy). `#hdr` has `will-change:transform,opacity` (it fades/shrinks on scroll in `sc()`), so the glass inside it (week panel, pill) has no backdrop blur: blur inside a fading group popped when scrolling back to the top. `glassShine()` reads no layout during scrolling (sizes cached).
  - **Sun/moon arch (synced to zmanim):** `skyCompute` places the body at x=`skyArcX(frac)`=50−58·cos(π·frac), y=`skyArcY(frac)`=102−52·sin(π·frac) % of the scene: a smooth half-ellipse whose ends lie beyond the screen edges (the body rises in and sets out along the curve, never drops straight down) and that clears the time pill; same in `skyPath` and `skyRun` (which uses the unclamped frac when setting). Before moonrise the moon shows dimmed low on the rising (left) side (frac .22). The body is above everything else in the header (z-index 5). The moon is a real photo disc `assets/moon-disc.jpg` lit by the true phase (`artMoonPhoto`), its dust trail (`skyTrailBuild`) follows the arch back toward the horizon. `skyTrail` clears the dust under the disc itself (soft-edged), because by day the moon's dark side is see-through. 
  - **Fonts are self-hosted** (`fonts/`: Figtree variable, Frank Ruhl Libre, Noto Serif Hebrew; no Google Fonts, which is blocked/slow in China), the two main ones preloaded.
  - **Smoothness rules:** the chip-to-card morph (`mz`) does nothing once settled and has no per-frame shadow; `sc()` doesn't rewrite unchanged attributes and sets `.cc-away` on the root when the home screen is scrolled away, which pauses the floating; `skyApply` only writes values that changed (it runs every 30 s); the moon dust trail is rebuilt only every ~1/90 of its arch; the dock does not float (it has a blur behind it).
  - **Event chips at the bottom (`#foot .chips2`)** stay on one row that scrolls sideways (with faded edges); they used to wrap into several rows over the week panel, and see-through chips on top of each other looked messy. Keep anything new there from stacking or overlapping. `footPlace()` (after each render, on resize and when fonts load) pins the row 14px under the week panel and above the + button; on short screens it shrinks the sky scene's height instead (min 150px).
  - **Semicircle = airy 3D glass dome (lit atmosphere):** `.sky-scene::after` is the top-half dome (true circle, conic mask `--dl`). Owner wants the SHAPE but 3D and airy: soft glowing rim (a `closest-side` ring gradient, no hard border), a lit crest, a faint interior haze, and a bloom of atmosphere on the rim beneath the sun/moon (`--lx/--ly` = dome-box point under the body, `--li` brighter near horizon, `--lc` warm sun / cool moon — all from `skyDomeAim`). `.sky-scene::before` is a wider soft halo for airiness (breathes `domeBreath`, fades on scroll). The dome never aim-rotates at rest (that felt like a solid piece moving — only the light moves); on scroll it rolls into a backwards C and is eaten away (`dmW`, `--dl`). Switches: `aim` (light follows body), `dome` (scroll roll). Don't go back to a hard 1px border or an aim-rotating shell.
  - **Empty middle → big stacked date (like the Pixel lock-screen clock):** `skySideSet(st)` (from `skyScene`/`skyUpdateScene`) puts `.sky-side` on `#hdr` when the body is below the horizon or more than 34% from the centre. The sky scene shrinks, and the Hebrew date (`.hd-big` = `.hd-d` day + `.hd-m` month) becomes a tall two-line block, day above month, about 16vh per line; the week panel stays where it was. A state, not animated (owner's wish).
  - **Rise/set caption under the big date:** in `.sky-side` the scene pill is hidden and `#skyCap2` (filled by `capSync()`) shows the same caption under the date.
  - **No "next special day" round button on the home screen** (`#nxc`, `nextUp()` keeps it hidden; owner's choice): upcoming days show only in the Coming Up column further down; the tiles' morph starts from the arrow.
  - **Daytime moon:** with the light theme (`data-theme="light"`) the photo moon's unlit side is transparent, as the real moon looks by day (`artMoonPhoto` alpha; cache keys carry a `d`); `skyApply` refreshes `img.mimg` when the theme flips.
  - **Hebrew date style:** plain ivory (night) / ink (day) with a soft shadow. A liquid-glass version (gradient fill clipped to text, outline, scroll glint) was tried and rejected by the owner ("looks like PowerPoint"): avoid gradient-filled/outlined lettering.
  - **One glass look everywhere** (block "One look for every card, sheet and button" in `cc-night-ui`): theme vars `--gx-*` per `data-theme` (dark sky → translucent navy glass, light sky → white glass). Covers cards (`.panel`, `.hyc`, `#p .ev`), Coming-up tiles (`#rail .rt`, tinted by kind), the sticky bar `.cb`, all sheets (`.sheet`, `.ai-card`, `.dmc`, `.stsp`, blurred), inputs inside them, buttons (`.btn` primary = ivory at night / navy by day, `.btn.gh` glass), and month cells (`#g .day`, kind tints as thin coloured borders; the old `.w-*` tints are `!important`, so overrides are too). Scrolling cards get no blur (smoothness). Switch: `glassui`.
  - **Header:** `.hd-big` Hebrew date in 'FRL App' (Frank Ruhl Libre, `fonts/`), the year on its own small line (no lines or diamonds: the owner found them bookish), `.hd-en`, glass week panel (`wkStrip`: `<u>` letter + `<b>` number; selected = navy circle with ring, events = teal dot). Dock ‹ › arrows hidden (swipe / week strip change days).
- **Sky effects (newest work):** `SKYA` state. `skyTrail()` / `skyTrailBuild()` draw the "breath on a window" streak (built once offscreen, then revealed). `skyPlan()` + `skyRun()` play the opening sun/moon animation after the logo finishes: the sun rises to its place; the moon rises to its place; after sunset the sun sets while the sky darkens; after moonset before sunrise the moon rises and sets. `skyWarm()` prepares artwork during the logo. `skyReplay()` reruns it after 5+ minutes away. It is skipped with reduced motion. Movement uses `transform` only, and root colour variables are updated sparingly, for performance.
- **Shiur reader:** tapping a Chitas/Rambam row (not its circle) opens `rdOpen(k)`, a full-screen Hebrew reader that loads that day's text from Sefaria's open API (CORS allowed): `rdCal()` (calendars: Parashat Hashavua aliyot, Tanya Yomi, Daily Rambam 1/3 chapters), `rdRefs()`, `rdText()`, `rdFlat()` (nested arrays → chapter/verse), `rdTanya()` (Tanya Yomi gives only the start; the portion runs to tomorrow's start), Rashi woven under each verse, combined parshiyos read both aliyos. The reader reads `sefaria/…json` on the site first (`rdLocal`). If that's missing and the phone can't read Sefaria directly ("Failed to fetch", seen on the owner's phone), `rdJ()` falls back to the push server's `/sefaria/…` relay (only calendars, v3 texts and v2 index; cached a day) and remembers that (`cc_rd_relay`). Leaving it (← or phone back, via `history.pushState`/`popstate`) checks the shiur off only if the text loaded **and was scrolled to the end** (`RDS.maxF` ≥ 99.5%); otherwise the reading place is kept per profile, day and shiur (`rdPosGet/rdPosSet`, key `cc_rd_pos`, last 40) and the reader reopens there. Finishing clears it. The circle (`.bx`) toggles without opening. `heN()` = Hebrew numerals (the app's `G()` is not a general one). Sefaria is blocked from the editing workspace; test with saved responses.
- **Chitas streak and stats:** `streakInfo()`, chip `#stk` → `stsOpen()`: a bottom sheet with Week / Month / Year / All time pages (horizontal scroll-snap), 270° rings (`sRing()`), per-shiur cards. CSS classes there are prefixed (`shero`, `smc`, `ssm`…) because the app already uses short names like `.hero`, `.mc`, `.sm`. Haptics come from the `H` object (`H.tap/sel/ok`).
- **Plan something (the scheduling bot):** `aiPlan()` → `aiSplitRequests()` (one card per request) → `aiInterpretSeg()` (reminder phrases via `aiRemParse()`, exceptions via `aiExceptParse()`/`aiApplyException()`, "because I have…" via `aiReasonEvent()`) → `aiLocalInterpret()`. Saved by `aiCommit()`; a plan may carry `rem` (reminder rules) and `tm` ("HH:MM"). Voice fixes: `AI_VOICE_FIX`.
- **No manual "Add an event" form** in the ⋯ sheet (the assistant adds events). The form (`#fwrap`, `fill(e)`) only appears as "Edit event" when editing an existing event.
- **Reminders:** `notifPlan()` builds (including the user's own plans' `rem` reminders, setting `mine`) "one reminder per occasion" threads; settings sheet `rmOpen()`; in-app cards `rcRender()`. Web push: `PUSH_DEFAULT` holds the server address, `pushTurnOn()`, `pushSync()` (POST `/sync` with future items; each item's body lists everything so far in its thread, and `tag` makes the phone replace the earlier notification), `nTest()` → `/test`.

## Push server (server/worker.js)
Endpoints: `GET /vapid` (public key, generated once into KV), `GET /sefaria/<api path>` (Sefaria relay for the shiur reader), `POST /sync`, `/unsub`, `/test`. The cron sends due items (15-minute grace window), uses an `idx` key so each minute costs one KV read, and rebuilds the index every 10 minutes (KV free plan allows about 1000 list calls a day). RFC 8291 encryption was verified against the RFC test vector.

## Native Android wrapper (widget + offline alarms) — `native/`
A thin Capacitor wrapper so the owner gets a home-screen widget and alarms that ring without Google push (unreliable in China). It is **not** a rewrite: `server.url` in `native/capacitor.config.json` points the WebView at the live GitHub Pages site, so the app always runs the current web app.
- **Alarms already work through the web app:** `notifSync()` → `NP()` (Capacitor `LocalNotifications`) schedules OS-level notifications with `allowWhileIdle` when `window.Capacitor` is native. No push needed. Packaging it with `@capacitor/local-notifications` is what turns these on.
- **Widget bridge (web side):** `ccBridge()`/`ccBridgeSoon()` in index.html write a `cc_widget` digest (Hebrew+English date, today's special days, today's tasks) via Capacitor `Preferences` when wrapped; a no-op in a normal browser. Called from `render()` and `notifSync()`. The native widget reads SharedPreferences store `CapacitorStorage` key `cc_widget`. (Widget UI itself = Milestone 2, not built yet.)
- **Build:** `.github/workflows/build-apk.yml` builds a debug APK on GitHub (push to `native/**` or manual run) and publishes it to the `apk-latest` release so the owner downloads `ChabadCalendar.apk` from a stable link. `native/patch-android.js` adds exact-alarm/boot/notify permissions after `npx cap add android`. The owner can't build locally (phone-only); CI is the only APK source, and its logs are how to debug build failures.
- **Controlled only through the web app:** the app has no settings UI of its own — it runs the web app, so the Reminders screen drives the native alarms directly. In a browser, `appSync()` adds an “App” section in ⋯ (download link on Android, “you’re using the app” when `CC_NATIVE`, “Android only” elsewhere) and `appFirstRun()` shows the install prompt (`appShow()`, `APK_URL`) once per profile on first sign-in (Android browser only, flag `cc_app_seen`). `CC_NATIVE` = `Capacitor.isNativePlatform()`.
- Known gap: the app’s WebView has its own localStorage, separate from Chrome, so a profile/events set up in the browser do not appear in the app (and vice-versa) — no cross-store sync yet. If the owner wants browser↔app parity, that needs server-synced profiles/settings (bigger).
- appId `com.mosheliberman.cdate`. `native/android/` and `node_modules/` are gitignored (regenerated in CI).
