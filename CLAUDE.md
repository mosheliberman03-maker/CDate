# CDate: Chabad Calendar (notes for Claude)

This repository is a hosted web app: a Chabad/Jewish calendar that is installed on the owner's phone (Pixel 6 Pro, Android) from GitHub Pages and sends push reminders. The owner works **from a phone only** and is not a programmer. Explain things in plain words, one step at a time, and do the git work yourself.
- **Links (owner's standing rule): always send every link in a text box (a code block), on its own line, so it can be copied easily on the phone.**
- **Version number (owner's standing rule): end every update message with the app's shown version number ("Version X.Y.Z", from `ccVerStr()`), e.g. a last line `📱 Version 12.4.1`.**

- Live site: https://mosheliberman03-maker.github.io/CDate/ (GitHub Pages, `main` branch, root folder)
- Push server: https://cdate-push.mosheliberman03.workers.dev (Cloudflare Worker named `cdate-push`, source in `server/worker.js`)
- Owner's location default: Foshan, China (timezone Asia/Shanghai). Users: fewer than a few dozen people.

## Files
| File | What it is |
|---|---|
| `index.html` | The whole app in one file (HTML + CSS + JS, about 380 KB). Edit it directly. |
| `sw.js` | Service worker (registered for every user on load): shows push notifications, focuses the app on tap, and keeps one saved copy of the app (cache `cdate-app-v1`): opening answers instantly from it and fetches the newest copy in the background; if that changed, it messages the page (`cdate-update`) and a "Tap to update" button appears. Fonts, `assets/` and icons are served from cache `cdate-static-v1` (stale-while-revalidate: instant and offline, refreshed in the background; rename a file to force a change through at once). |
| `hayomyom-en.json` | English Hayom Yom (Chabad.org translation, used with permission; the owner holds the written permission), keyed `"<monthKey>-<day>"` like `Ki-19`, `AI-14`. Each entry `{h: original date heading, p: [paragraph HTML with only b/i/br], t: 1 if translated in the app}`. 12 entries (13 dates) were translated from the Hebrew/Yiddish because the collector picked up the original. Loaded by `hyFill()`; the service worker keeps a saved copy. |
| `tools/` | The phone-browser bookmark tools used to collect it (Chabad.org blocks server downloads, 403); `prefetch-shiurim.js` (nightly shiur texts); `worker.html` (copy page for the server code). |
| `sefaria/` | Shiur texts saved nightly by `.github/workflows/shiurim.yml` (about 03:15 China time; yesterday to 8 days ahead). Sefaria's Cloudflare protection blocks live requests from the app on the owner's phone and from Cloudflare Workers, but answers GitHub's servers. The script runs the app's own reader (`rdBuild`) headless and saves the trimmed Sefaria replies under the names `rdLocal()` looks for. Texts are kept (they repeat in later years); day schedules older than 3 days are deleted. |
| `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png` | Install metadata and icons: **since v55 the simplified curious character** (no eyebrows, head tilted, eyes looking up to the side, white halo) on a navy gradient; rendered from `CCH_SVG` in a headless browser (scratchpad `icon.js`). |
(The in-page favicon `<link rel="icon">` is a base64 64px copy of the same character icon (v55, owner: the character replaces the aleph everywhere). The native APK icon and splash come from `native/assets/icon.png` / `splash.png` (same character; splash = navy with him in the middle).)
| `server/worker.js` | Cloudflare Worker source. **Not served from here**: changes must be pasted into the Cloudflare dashboard by the owner (Workers & Pages, then cdate-push, then Edit code, then Deploy). Needs KV binding `KV` and cron `* * * * *`. |

**GitHub Pages publishing can get stuck** ("Deployment request failed … due to in progress deployment"), especially after several quick pushes. Fix: run the `unstick-pages.yml` workflow (cancels deployments GitHub still thinks are in progress, then requests a fresh build). Avoid many pushes to `main` in a row. `tools/worker.html` has a Copy button for pasting `server/worker.js` into Cloudflare from the phone.

Do not add files named `index (1).html` or similar: only `index.html` is served. GitHub Pages tells browsers to cache for about 10 minutes, but the service worker bypasses that. **Updates apply themselves (owner, v27):** when the service worker reports a new copy (`cdate-update` → `ccAutoUpd`), the page reloads on its own if you haven't touched it yet (within 25 s of opening or returning) or as soon as you leave the app (reload while hidden); otherwise the "Tap to update" bar shows. Such a reload sets `sessionStorage cc_quiet` → `window.CC_QUIET`, which skips the logo intro and the opening sun/moon animation. Returning to the app asks the service worker for the newest copy (`fetch(location.pathname)`). Never auto-reload while a sheet, the reader, the assistant or the tour is open (`auBusy`).

## Push server (server/worker.js)
Endpoints: `GET /vapid` (public key, generated once into KV), `GET /sefaria/<api path>` (Sefaria relay for the shiur reader), `POST /sync`, `/unsub`, `/test`, `/acct/new|login|sync` (calendar accounts, v89), `/kit/*` (Keep in Touch). The cron sends due items (15-minute grace window), uses an `idx` key so each minute costs one KV read, and rebuilds the index every 10 minutes (KV free plan allows about 1000 list calls a day). RFC 8291 encryption was verified against the RFC test vector. **Origin lock:** `/sync`, `/unsub`, `/test` and the `/sefaria/` relay require the request `Origin` (or `Referer`) to be in `ALLOW` (the live GitHub Pages site + localhost + capacitor); CORS reflects only the owner's origin (`corsFor`). Stops a browser-based copycat front-end hosted elsewhere from using this server; does NOT stop a hand-forged request that spoofs Origin. `/vapid` and `/` stay open. Deploy = owner pastes `server/worker.js` into Cloudflare (via `tools/worker.html` Copy); **then check the Deployments tab: if the new version ("Updated Script") is not the Active deployment, tap its ⋯ → Promote version** (seen Nov 2026: Deploy in the editor only saved a version). Quick check that the new code is live: open `/kit/phones3` in a browser → "did not come from the Keep in Touch app" (old code says `not found`). `tools/worker.html` embeds a copy of the worker: regenerate it whenever `server/worker.js` changes; if reminders/shiurim break after, loosen `ALLOW`.
